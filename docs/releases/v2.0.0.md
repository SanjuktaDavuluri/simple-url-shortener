## Evidence

- **Delivery metrics** ([`delivery/metrics.md`](../../delivery/metrics.md)): 6 of 6 Runs fully delivered; 0 of 39 Lanes rolled back; 20 retries in 131 Stage executions (15.3%); MTTR 6m 36s over 18 recoveries; mean end-to-end latency 13h 25m, of which 3h 16m excluding human wait; $72.57 in all ($12.10 per Run). Per-Run Event Logs and reports are in `delivery/runs/R-0001` to `R-0006` and verify with `orchestrate verify --all`.
- **Required checks on `main`:** Verify (format, compile, Error Prone, unit and integration tests), Browser checks (Playwright and Lighthouse, median of 3, ≥ 90 in every category) and Orchestrator (ruff, mypy, pytest). A fourth job, Container (image build and container tests), runs on every PR but is not a required check.
- **Tests:** every spec has a coverage section in the [integration-testing plan](../plans/0001-integration-testing.md) tracing user stories to tests. The orchestrator suite (294 tests at close-out) drives the `orchestrate` command with a scripted agent and an in-memory GitHub.
- **Traceability:** roadmap item → spec → tickets → PRs (each `Closes #n`) → Run report → this note.

## Deferred, and why

- **#78, agent shell steps loading the user's interactive shell** and **#82, `board-status.sh` missing Issues beyond the board's first 100 items:** neither blocked a Run once worked around, so both moved to Release 3.
- **The container job is not a required check.** Making it one is a branch-protection change, left for the maintainer to decide.
- **Release 3** (rate limiting, security headers, private-address Rule, risk register, load and failure testing, write-ups) is designed and was not started, by plan. Items beyond it (PostgreSQL, scaling out, custom aliases, edit and delete) stay on the [roadmap](../roadmap.md) with their reasons.

## Lessons learned

- **Parallel Lanes collide on shared documents.** Several PRs editing the same README rows and plan matrix conflicted. Two fixes: conflicts in shared docs merge row by row (#77), and each ticket writes its user-facing notes to `docs/Issue-<n>-readme.md` instead of the README (#149); this close-out folded those notes into the README once.
- **Two green PRs can break `main` together.** #153 and #154 each passed CI and failed once both were merged (#157, #158). A PR now takes in `main` and re-runs its checks before a merge is requested (#76).
- **An agent can propose something plausible and wrong.** One spec amendment carried a one-line placeholder in place of the 339-line spec; a human caught it in the diff. Amendments are now checked before approval is requested, and the request shows the diff (#170).
- **A spec's `status:` line is not part of what was approved.** Marking a spec `implemented` forced a nine-ticket re-plan of shipped work. The lineage hash now ignores it (#170).
- **Policy checks should look at what a command contacts, not what it mentions.** URLs in commit messages and heredocs paused Lanes. Only the programs that connect to a URL are checked now, and newline-separated commands are judged one by one (#170).
- **Cost fell as the work narrowed.** R-0005 and R-0006 cost $2.45 and $3.10, against $12.72 to $20.96 for R-0001 to R-0004. They ran after per-step model and effort routing (ADR 0024) and had smaller scope, so the metrics do not separate the two causes.
- **Process:** the delivery board still needs an explicit move to Done after a merge, which `scripts/board-status.sh` does.
