## Evidence

- **Tests:** 52 unit tests and 37 integration tests, with every Rule tested on its own. Branch coverage was 100% when measured ad hoc; coverage reporting in CI is roadmap R17.
- **Browser:** 16 Playwright checks in real Chrome, with JavaScript on and off: no reloads, inline errors, copy-to-clipboard, focus handling, and no console errors or 404s. **Lighthouse 100** in every category on mobile and desktop (the gate is ≥ 90).
- **CI:** both checks are required on `main`. Every change reached `main` through a PR linked to its ticket.
- **Traceability:** spec 0001 → tickets #3–#8, #14, #16 → PRs #12–#21 → [integration-testing plan](../plans/0001-integration-testing.md) traceability matrix.

## Deferred, and why

Everything postponed is in the [roadmap](../roadmap.md) with its reason. The main items:
- custom aliases (R1), expiring links (R3) and edit/delete (R4), which are brownfield features added to the running system later
- PostgreSQL (R5) and horizontal scaling (R15), which happen only when measurements call for them (ADR 0019)
- the Docker image (R11) and health checks, metrics and logs (R12), in Release 2

## Lessons learned

- **Test isolation with Spring's context cache:** per-test temporary database directories broke cached contexts (`SQLITE_READONLY_DBMOVED`). Fixed with one database per context, reset with Flyway clean + migrate before each test (#14).
- **Routing:** `/favicon.ico` was being treated as a Short Code. Restricting the Redirect route to exactly 7 base62 characters fixed it, and the route now documents the Short Code format (#8).
- **HTMX doesn't swap `4xx` responses by default.** Configuring `responseHandling` let `422` and `503` messages render inline (#7).
- **Documentation drift:** a README example showed an incorrect `422` body. Examples are now copied from real output.
- **Process:** the delivery board's "closed → Done" automation is off, so moving a ticket to Done is an explicit step in the charter.
